# Frontend Design & UI/UX Architecture

This directory documents the user interface and user experience (UI/UX) architecture of the **Agentic Multimodal Research Platform** web application (`apps/web`).

---

## 1. Overview & UI Philosophy

The frontend is a modern single-page application built with **React 18**, **TypeScript**, and **Vite**.

### Design Goals:
- **Clarity over Clutter**: Present complex agentic DAG states, multi-source evidence, and long-form synthesis reports in a structured, legible manner.
- **Real-Time Responsiveness**: Live updates via WebSocket streaming without page refreshes.
- **Local Design System**: Built with clean Vanilla CSS variables and utility classes, avoiding heavy UI component libraries.

## 3. Primary Application Screens

1. **Dashboard (`/dashboard` or `/`)**:
   - Lists recent research jobs with pagination.
   - Status badges (`Pending`, `Running`, `Completed`, `Failed`).
   - Quick action to initiate a new research job.
   - Handled empty states and error recovery banners.

2. **New Research Job (`/research/new`)**:
   - Inquiry formulation form (Research Question, Context, Constraints).
   - Validation and submission progress indicators.
   - Informational helper card with best practices for research queries.

3. **Research Detail View (`/research/:id`)**:
   - Top-level job header with dynamic status indicator and back navigation.
   - Six distinct tabbed views:
     1. **Overview**: Key metrics, domain, creation date, completed task count, and constraints.
     2. **Plan**: Strategic research decomposition plan generated by the Planner.
     3. **Tasks**: Live DAG execution table showing individual task objectives, assigned agents, and status.
     4. **Sources**: Collected web and document source cards with URLs and retrieval timestamps.
     5. **Evidence**: Extracted atomic claims, confidence percentages, supporting quotes, and verification status.
     6. **Report**: Structured synthesis containing Executive Summary, Methodology, Findings, Conclusions, and Limitations.
   - Resilient real-time WebSocket connection with automatic snapshot hydration.

4. **Settings (`/settings`)**:
   - Model provider configuration (Ollama URL, default LLM, Vision, and Embedding models).
   - General platform settings (Log Level, Max Upload Size).
   - In-app feedback and notification alerts.

## 4. Navigation & Layout

- **Header / Navigation Bar**: Global application title, logo badge, and navigation links (`Dashboard`, `New Research`, `Settings`).
- **Main Container**: Responsive container with max-width constraints ensuring readability on wide displays.
